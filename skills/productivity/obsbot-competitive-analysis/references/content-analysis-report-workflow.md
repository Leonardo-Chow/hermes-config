# 内容分析报告工作流（博主合作数据表 → 内容分析报告）

当用户提供「博主合作数据表.xlsx」+ 一个「内容分析报告」样例（如 Razer/Logitech/Elgato IP 联名分析），要求"按这个格式把文档写完"时使用。

## 模板列结构（内容分析报告样例，14 列）

```
品牌 | 产品 | IP | 平台 | 内容链接 | 博主类型 | 内容主题 | 内容形式 | IP呈现方式 |
关键词（标题/Hashatg）| 博主关注点 | 用户关注点 | 样本Insights | 整体insights/合作建议
```

- 样例中 品牌/产品/IP 按品牌合并单元格；同品牌多平台时 平台列 再按平台合并（Youtube/Instagram）
- **N 列（整体insights/合作建议）整列合并**（如 N2:N19），写覆盖全表的总体洞察段落
- 每条内容行填写：内容主题、内容形式、IP呈现方式、关键词、博主关注点（编号列表）、用户关注点（编号列表）、样本Insights（2-3 条可执行洞察）
- 报告尾部（合并列内）写总结：平台投放分布 / 红人选择趋势 / 内容方向 / IP 或卖点在内容中的作用

## ⚠️ 用户明确要求（2026-08-04 两次强调）

1. **不要改变表格内容顺序** — 按原表行顺序填写
2. **不要改变表格结构** — 用户上传的 15 列博主合作数据表保持 15 列，只把空缺/占位列补上（占位符 `1` 和无值单元格），不要改成模板的 14 列合并样式
3. **整体insights/合作建议 合并成一条** — 该列整列合并（如 O2:O22），写一条覆盖全表的整体合作建议（平台策略/红人选择/品牌差异化/风险执行），不要每行单独写
4. 分析必须基于真实抓取的数据（caption + 评论），不能编造用户关注点

## 博主合作数据表列结构（15 列，用户上传的原始格式）

```
品牌 | ID | 博主链接 | 博主类型 | 产品 | 账户平均曝光/k | 账户平均互动率 | 内容链接 |
内容主题 | 内容形式 | 关键词（标题/Hashatg）| 博主关注点 | 用户关注点 | 样本Insights | 整体insights/合作建议
```

常见状态：内容主题/内容形式/博主关注点 = 占位符 `1`（要替换）；用户关注点/样本Insights/整体insights = 空（要填写）。

## 执行步骤

1. `read_file` 读 xlsx → 再用 openpyxl 逐格确认：max_row/max_column、合并单元格、每行哪些列是占位符 `1` 或 None
2. 提取有效行（跳过全空行），打印每行 ID + 产品 + 内容链接
3. 抓真实数据（详见 instagram-follower-batch-fetch skill「帖子级内容获取」节）：
   - 单帖 og:description（匿名 curl，短 UA + X-IG-App-ID）→ caption + likes/comments
   - 评论 API（需 cookie）→ 用户关注点 的真实依据
   - 去重 URL 缓存抓取结果；间隔 1-1.2s
4. 逐行填写 6 列：内容主题（从 caption 概括）、内容形式（Reels/图片）、博主关注点（博主实际表达，编号列表）、用户关注点（真实评论归纳，编号列表）、样本Insights（2-3 条）、整体insights（合并列一条）
5. **整体合作建议合并列写法**（用户认可的四段式）：
   - 一、平台与内容策略（IG 种草+转化、参数罗列型互动差应引导 YouTube、促销机制）
   - 二、红人选择（垂类化+生活化趋势、审美型/Study With Me/Music/Gamer 各自定位）
   - 三、品牌差异化投放（各品牌卖点演示方式）
   - 四、风险与执行提醒（负面反馈监控、标注 #ad/gifted、Brief 细节要求）
6. 保存到 `~/Downloads/`，文件名标注 `_已补全`
7. **验证**：openpyxl 逐格比对原文件 vs 新文件，非空缺列必须零改动；打印 MERGED 范围确认合并正确

## 实战陷阱

- **openpyxl 合并单元格**：合并后只有左上角保留值，其余为 None。写合并列时先 merge 再给左上角赋值；逐格验证时注意合并区内的 None 是正常的
- **品牌分组偏移 bug**：合并品牌列时 end_row 计算易差 1（rows[i] 在 Excel 行 = i+2）。用分组边界公式 `(start, i+1)` / 末组 `(len(rows)+1)`，生成后打印 MERGED 核对
- **占位符 `1`** 出现在内容主题/内容形式/博主关注点列 = 待填信号，不是数字数据
- **重复行**：同一链接可能在表中出现多次（数据表去重逻辑）——用户说"不要改变顺序/结构"时保留原行，内容相同即可
- **主页链接冒充内容链接**（如 `instagram.com/audreycaprianni/`）：og:description 是粉丝数格式，无法分析单帖 → 标注"主页链接，需人工确认"，不要硬编
- **产品列与 caption 不符**：以 caption 为准并修正（如标 Facecam 实为 Prompter、标 Link 2C 实为 Link 2 Pro），报告中注明
- **官方号转发 KOC**（caption 作者 ≠ 博主 ID）：标注"官方转发"，互动数据参考价值低
- **负面评论要预警**：评论区出现兼容性吐槽（如 Win11）时在 insights 里标 ⚠️，不要忽略
