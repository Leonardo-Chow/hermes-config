# 小黑日报助手数据查询

## 服务信息

- **本地 HTTP 服务地址**: `http://127.0.0.1:8088`
- **文档端点**: `GET /` — 返回 Markdown 格式的 API 文档

## ⚠️ 强制规则（必须遵守）

1. **每次处理用户请求前，必须先调用 `GET http://127.0.0.1:8088/` 获取最新 API 文档。** 绝不可依赖记忆中的固定 API 列表，必须以实时拉取的文档为准。
2. 读取 Markdown 文档后，解析出接口列表、参数定义、请求示例和响应结构，再动态选择接口并构造请求。
3. 所有业务接口返回统一 JSON 格式：`{"code": 0, "message": "success", "data": null}`

## 操作流程

### Step 1: 拉取最新 API 文档

```bash
curl -s http://127.0.0.1:8088/
```

返回 Markdown 文本，包含所有可用接口的路径、方法、参数、请求示例和响应示例。

### Step 2: 解析文档

从 Markdown 中提取：
- 接口路径（如 `/api/timeline`、`/api/report` 等）
- HTTP 方法（GET/POST）
- 参数名称和格式
- 请求/响应示例

### Step 3: 根据用户意图选择接口并构造请求

根据用户自然语言查询，匹配最合适的接口，构造 curl 命令调用。

## 已知能力范围（仅供参考，以实时文档为准）

| 能力 | 说明 | 时间参数格式 | 默认值 |
|------|------|-------------|--------|
| 工作时间线查询 | 按时间范围查询工作记录 | `YYYY-MM-DD` 或 `YYYY-MM-DD HH:mm:ss` | 今天 |
| 工作报告查询 | 查询工作报告，返回 Markdown 格式内容 | `YYYY-MM-DD` | 今天 |
| 时段热力图查询 | 查询每日 24 小时分布的热力数据 | `YYYY-MM-DD` | 近 7 天 |
| 应用使用时长查询 | 查询各应用使用时长汇总，按时长降序 | `YYYY-MM-DD` 或 `YYYY-MM-DD HH:mm:ss` | 今天 |

## 参数规范

- **日期格式统一**: `YYYY-MM-DD`（如 `2026-06-16`）
- **精确时间格式**: `YYYY-MM-DD HH:mm:ss`（如 `2026-06-16 09:00:00`）
- **未指定日期时**: 默认查询今天
- **不分页**: 本地数据库查询，直接返回全量数据

## 自然语言映射规则

| 用户说 | 对应能力 |
|--------|---------|
| "今天做了什么" / "工作时间线" / "工作记录" | 工作时间线查询 |
| "工作报告" / "日报" / "总结" | 工作报告查询 |
| "热力图" / "什么时候最忙" / "时段分布" | 时段热力图查询 |
| "用了什么软件" / "应用时长" / "屏幕时间" | 应用使用时长查询 |

## 执行模板

```bash
# Step 1: 拉取 API 文档
API_DOC=$(curl -s http://127.0.0.1:8088/)

# Step 2: 解析文档，确定目标接口路径和参数

# Step 3: 调用具体接口（示例）
curl -s "http://127.0.0.1:8088/api/xxx?startDate=2026-06-16&endDate=2026-06-16"
```

## 注意事项

- 服务为本地 HTTP，无需认证
- 服务未启动时返回 connection refused，需提示用户启动服务
- 不做分页处理，返回全量数据
- 响应中 `code=0` 表示成功，其他值表示错误
