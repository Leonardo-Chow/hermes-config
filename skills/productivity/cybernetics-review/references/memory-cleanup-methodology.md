# Memory 清理方法论

## 触发条件
- Memory 使用率超过 70%
- 用户主动要求清理
- 定期维护（建议每月一次）

## 清理流程（控制论闭环）

### Step 1: 输入 — 扫描 Memory 全貌
```
1. 读取当前 memory 所有条目
2. 统计使用率（字符数/上限）
3. 分类每个条目：环境事实 / 用户偏好 / 操作细节 / 历史数据 / 重复
```

### Step 2: 处理 — 四步清理法

#### 2.1 删除重复条目
- 检查是否有相同或高度相似的条目
- 保留最完整的一份，删除其他

#### 2.2 删除过时条目
- Cron job 已禁用/删除的
- 工具已卸载/替换的
- 问题已修复的（如 "Tavily MCP 连接问题"）

#### 2.3 迁移操作细节到 Skill
- 检查条目内容是否已存在于某个 skill 中
- 如果 skill 已覆盖 → 直接删除 memory 条目
- 如果 skill 未覆盖 → 先 patch skill，再删除 memory 条目

#### 2.4 精简冗长条目
- 对于保留的条目，检查是否可以压缩
- 引用 skill 的条目可以大幅精简（"详见 xxx skill"）
- 列表类条目合并为一行

### Step 3: 输出 — 验证清理结果
```
1. 确认使用率降到目标值（建议 <50%）
2. 确认没有误删重要信息
3. 确认 skill 中有对应内容
```

### Step 4: 反馈 — 记录清理结果
- 记录清理前后的使用率
- 列出删除/迁移的条目
- 标注需要后续关注的条目

### Step 5: 修正 — 更新清理流程
- 如果发现新的清理模式，更新本文档
- 如果发现 skill 缺失内容，补充 skill

## Memory 格式最佳实践

### 条目分隔符
- 使用 `§` 作为条目分隔符
- 但 `memory` 工具不支持 §，需要逐条操作

### 条目长度
- 单条目建议 <200 字符
- 超过 300 字符的条目应考虑拆分或迁移

### 引用格式
```
[主题]：[核心信息]。详见 [skill名] skill。
```
示例：
```
复盘数据分流：底层逻辑→memory，操作细节→skill，历史数据→IMA。详见 cybernetics-review skill。
```

### 避免的格式
- ❌ 过长的列表（>5 项）
- ❌ 详细的操作步骤（应放 skill）
- ❌ 已存在的 skill 内容的重复

## Memory 工具操作陷阱

### replace 操作
- `old_text` 必须精确匹配（包括空格、换行）
- 不支持正则表达式
- 建议先用较短的 unique substring 匹配

### remove 操作
- 同样需要精确匹配
- 如果匹配失败，尝试更短的 substring

### 批量操作
- 不支持批量删除/替换
- 需要逐条操作
